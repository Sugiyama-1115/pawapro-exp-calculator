# 05. 画面仕様

対応環境は **PC の Chromium系ブラウザ最新版のみ**。スマートフォン専用レイアウトは実装しない。
表示言語は日本語のみ。

---

## 1. 全体レイアウト

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ヘッダー                                                              │
│  パワプロ必要経験点計算   [ゲーム: パワプロ2024-2025 ▼]  [プラン一覧] │
│  ※ サンプルデータ選択時はここに黄色の注意バッジを表示                 │
├──────────────────────────────────────────────────────────────────────┤
│ タブバー                                                              │
│  [1 選手設定] [2 基礎能力] [3 特殊能力] [4 変化球] [5 計算結果]        │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  タブコンテンツ（スクロール領域）                                      │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ 結果サマリーバー（常時表示・画面下部に固定）                           │
│  筋力 1,820 / 敏捷 430 / 技術 2,240 / 変化球 1,650 / 精神 1,310       │
│  合計 7,450             [推定含む]  [不足 2件]                        │
└──────────────────────────────────────────────────────────────────────┘
```

| 領域 | 規定 |
|---|---|
| 最小対応幅 | 1280px。それ未満では横スクロールを許容する。 |
| 最大コンテンツ幅 | 1440px。中央寄せ。 |
| 結果サマリーバー | `position: sticky; bottom: 0`。**全タブで常時表示**（FR-R-08）。高さ固定 72px。 |
| タブ切替 | クライアントサイドのみ。ページ遷移・URL変更を伴わなくてよい `[MAY]`。入力内容はタブ切替で失われない。 |
| フォント | OSの標準サンセリフ（`system-ui`）。**Webフォントを外部から読み込んではならない**（外部通信禁止）。 |
| 数値表示 | 3桁カンマ区切り（例: `1,820`）。0 は `0` と表示する。 |
| カラーテーマ | ライトテーマのみ。ダークテーマ対応は対象外。 |

## 2. 共通コンポーネント

### 2.1 結果サマリーバー（`ResultSummaryBar`）

| 表示要素 | 内容 |
|---|---|
| 5カテゴリの合計 | `筋力 / 敏捷 / 技術 / 変化球 / 精神` の順に固定 |
| 総合計 | 太字・他より大きく表示 |
| ステータスバッジ | `確定`（緑） / `推定含む`（黄） / `未完成`（赤） |
| 不足件数 | `issues` の件数。0件のときは非表示。クリックで計算結果タブの不足一覧へ遷移する |
| 計算中インジケータ | 再計算中は総合計の右に小さくスピナーを表示 `[SHOULD]` |

### 2.2 出どころバッジ（`SourceBadge`）

| `source` | 表示 | 色 |
|---|---|---|
| `master` | （バッジなし） | — |
| `measured` | `実測` | 緑 |
| `estimated_high` | `高信頼推定` | 橙 |
| `estimated` | `推定` | 黄 |
| `manual` | `手動入力` | 青 |

### 2.3 経験点テーブル（`ExpVectorTable`）

5カテゴリを常に同じ順序・同じ列幅で表示する共通コンポーネント。値が 0 のカテゴリは薄いグレーで表示する。

## 3. タブ1: 選手設定（`PlanSettingTab`）

### 入力項目

| 項目 | UI | 必須 | 既定値 | 制約 |
|---|---|---|---|---|
| ゲーム | セレクト | ○ | `games.json` の `defaultGameId` | 変更時は確認ダイアログ（§3.2） |
| 選手名 | テキスト | ○ | `新規プラン` | 1〜50文字 |
| 選手種別 | ラジオ（投手 / 野手） | ○ | 投手 | 変更時は確認ダイアログ（§3.2） |
| センス○ | ラジオ（あり / なし） | ○ | **あり（`sense_plus`）** | — |

### 3.1 データロード状態の表示

| 状態 | 表示 |
|---|---|
| `loading` | 「CSVを読み込み中…」＋スピナー。他タブは操作不可。 |
| `ready` | 読み込んだ行数の内訳を折りたたみで表示（例: 基礎能力 1,240行 / 青特 320行 …） |
| `error` | 赤枠のエラーパネル。`ValidationIssue` を一覧表示（最大200件）。他タブは操作不可。 |
| データ未配置 | 「このゲームのデータが配置されていません。CSVをインポートしてください。」＋インポートパネルへのリンク |

### 3.2 破壊的変更の確認

以下の変更は入力済みデータを無効化しうるため、**変更前に確認ダイアログを表示**する。

| 操作 | ダイアログ文言 |
|---|---|
| ゲーム変更 | 「ゲームを変更すると、選択中の特殊能力・変化球データが現在の入力と一致しなくなる場合があります。続行しますか？」 |
| 選手種別変更 | 「選手種別を変更すると、基礎能力・特殊能力・変化球の入力内容がクリアされます。続行しますか？」 |

- ゲーム変更: 入力内容はクリアしない。新しいゲームデータに存在しない `abilityId` は計算時に `*_DATA_MISSING` として報告する。
- 選手種別変更: `currentBase` / `targetBase` / `blueTargets` / `goldTargets` / `breakingPlan` をクリアする。

### 3.3 CSVインポートパネル（`CsvImportPanel`）

折りたたみ領域として本タブ内に配置する。

```text
▼ CSVインポート（標準データを上書き）

  基礎能力（センス○）     [ファイル選択]   状態: 標準
  基礎能力（通常）         [ファイル選択]   状態: 標準
  青特殊能力               [ファイル選択]   状態: インポート済 320行  [破棄]
  金特殊能力               [ファイル選択]   状態: 標準
  金特前提                 [ファイル選択]   状態: 標準
  コツ倍率                 [ファイル選択]   状態: 標準
  基礎能力定義             [ファイル選択]   状態: 標準
  設定(config)             [ファイル選択]   状態: 標準
  変化球キャッシュ(センス○) [ファイル選択]   状態: 標準
  変化球キャッシュ(通常)    [ファイル選択]   状態: 標準
```

- ファイル選択後、直ちに `03_data_spec.md` の検証を実行する。1件でも違反があれば**適用せず**エラー一覧を表示する。
- 適用したインポートデータは種別ごとに `[破棄]` できる。破棄すると標準データに戻る。
- インポート状態はゲームバージョンごとに保持する。

## 4. タブ2: 基礎能力（`BaseAbilityTab`）

### レイアウト

`base_ability_defs.csv` の `display_order` 昇順で表を生成する。**能力項目をコードにハードコードしない。**

```text
┌────────────┬──────────┬──────────┬────────────────────────────────────────┐
│ 能力        │ 初期値    │ 目標値    │ 必要経験点                              │
├────────────┼──────────┼──────────┼────────────────────────────────────────┤
│ 球速        │ [130]    │ [155]    │ 筋 900 / 敏 0 / 技 500 / 変 0 / 精 0    │
│ コントロール │ [ 35]    │ [ 80]    │ 筋 0 / 敏 0 / 技 450 / 変 0 / 精 300    │
│ スタミナ     │ [ 40]    │ [ 85]    │ ⚠ 84→85 のデータがありません             │
│ 守備力      │ [  1]    │ [  1]    │ —                                       │
│ 捕球        │ [  1]    │ [  1]    │ —                                       │
├────────────┴──────────┴──────────┼────────────────────────────────────────┤
│ 小計                              │ 筋 900 / 敏 0 / 技 950 / 変 0 / 精 300  │
└──────────────────────────────────┴────────────────────────────────────────┘

▶ 野手能力も入力する（投手プランのみ・折りたたみ）
```

| 項目 | 規定 |
|---|---|
| 初期値 / 目標値 | 数値入力。`min_value` / `max_value` の範囲でクランプする。`value_type = trajectory` はセレクト（1〜4）。 |
| 入力の反映 | `onChange` で即座にストア更新、200ms デバウンス後に再計算。 |
| 必要経験点 | 0 のカテゴリはグレー表示。全カテゴリ 0（目標=初期）の場合は `—` を表示。 |
| エラー行 | 行の背景を薄赤にし、経験点欄にエラーメッセージを表示する。 |
| 目標値 < 初期値 | 目標値入力欄を赤枠にし「目標値は初期値以上にしてください」を表示。 |
| 野手能力の折りたたみ | 投手プランのときのみ表示（FR-B-07）。開いた場合、`player_type = fielder` の定義行を同じ表形式で表示する。 |

### 5.1 検索（`AbilityPicker`）

| 項目 | 規定 |
|---|---|
| 対象 | `blue_abilities` と `gold_abilities` の `display_name` および `ability_id` |
| 一致方式 | 部分一致・大文字小文字を区別しない。日本語は正規化せず単純部分一致とする。 |
| 絞り込み | 現在のプランの `player_type` に一致する能力（`common` を含む）のみ表示する。 |
| 種別フィルタ | `すべて` / `青特` / `金特` |
| 表示件数 | 最大50件。超過時は「他 N 件」と表示する。 |
| 追加済み | すでに選択中の能力は `[+ 追加]` を無効化し `追加済み` と表示する。 |

### 5.2 青特の行

| 項目 | 規定 |
|---|---|
| 現在 / 目標 | `ability_type` に応じ `NONE/ON` または `G`〜`A` のセレクト |
| コツLv | 0〜5 のセレクト。既定値 0 |
| 自動追加行 | 🔗アイコンと「〇〇の前提として自動追加」を表示。**削除ボタンは表示しない**（金特を削除すれば消える） |
| 手動指定＋自動追加の重複 | 行は1つだけ表示し、「🔗 〇〇の前提でもあります」と併記する。コツLvはユーザー指定値を採用し、その旨を注記する。 |
| 表示順 | ユーザー指定分（追加順）→ 自動追加分（`ability_id` 昇順） |

### 5.3 金特の行

| 項目 | 規定 |
|---|---|
| コツLv | 0〜5 のセレクト。既定値 0 |
| 下位青特のコツLv | 0〜5 のセレクト。既定値 0。前提を持たない金特では非表示 |
| 前提表示 | `gold_prerequisites` の全件を列挙する。前提なしの場合「前提: なし」 |
| データ不足 | 経験点欄に「この金特の実測データがありません（`gold_abilities.csv` を確認してください）」を赤字表示 |

## 6. タブ4: 変化球（`BreakingBallTab`）

**野手プランでは本タブをタブバーから非表示にする**（FR-BR-08）。

### レイアウト

```text
┌─ 目標変化球構成 ────────────────────────────────────────────────────┐
│  [スライダー ▼] 変化量 [4 ▼]  [削除]                                 │
│  [カーブ     ▼] 変化量 [3 ▼]  [削除]                                 │
│  [フォーク   ▼] 変化量 [5 ▼]  [削除]                                 │
│  [+ 球種を追加]                          総変化量: 12 / 球種数: 3     │
└─────────────────────────────────────────────────────────────────────┘

┌─ 必要経験点の入力方式 ──────────────────────────────────────────────┐
│  ( ) 一括で入力する      ( ) ステップごとに入力する   (•) 未入力      │
└─────────────────────────────────────────────────────────────────────┘

  ※ 未入力の場合の表示:
  ┌───────────────────────────────────────────────────────────────┐
  │ ⚠ この変化球構成は未計測です。                                  │
  │   ゲーム画面に表示された必要経験点を入力してください。            │
  │   [一括経験点を入力]   [ステップごとに入力]                      │
  └───────────────────────────────────────────────────────────────┘
```

### 6.1 一括実測方式

```text
筋力 [   0]  敏捷 [   0]  技術 [ 450]  変化球 [1280]  精神 [ 100]
```

- 5項目すべてに 0 以上の整数を入力する。1つでも空欄なら未入力扱い（`BREAKING_DATA_MISSING`）。
- 入力値は `source = manual` として計上する。

### 6.2 ステップ実測方式

```text
┌───┬──────────┬────┬────┬──────────┬────────┬──────────────────────────┬─────────┐
│seq│ 球種      │ 前 │ 後 │ 前総変化 │ 前球種数│ 経験点(筋/敏/技/変/精)     │ 出どころ │
├───┼──────────┼────┼────┼──────────┼────────┼──────────────────────────┼─────────┤
│ 1 │ スライダー │ 1  │ 2  │    1     │   1    │ 0 / 0 / 10 / 50 / 0        │ [実測]   │
│ 2 │ スライダー │ 2  │ 3  │    2     │   1    │ 0 / 0 / 12 / 60 / 0        │ [手動]   │
│ 3 │ カーブ     │ 0  │ 1  │    3     │   1    │ ⚠ 未登録 → 入力してください │ —        │
└───┴──────────┴────┴────┴──────────┴────────┴──────────────────────────┴─────────┘

[+ ステップを追加]     [入力済みステップを共通キャッシュへ登録]
```

| 項目 | 規定 |
|---|---|
| `後`（toLevel） | `前 + 1` に自動設定。編集不可。 |
| 前総変化 / 前球種数 | 手入力。自動計算しない（取得順によって変わるため）。 |
| キャッシュ自動入力 | 4キーが揃った時点でキャッシュを完全一致検索し、ヒットしたら経験点欄を自動入力して `[実測]` と表示する。 |
| 手動上書き | キャッシュ自動入力後にユーザーが値を変更したら `[手動]` に変わる。 |
| キャッシュ登録 | ボタン押下で、経験点が入力済みの全ステップを共通キャッシュへ登録する。既存キーと重複する場合は確認ダイアログで上書き可否を問う。 |

## 8. プラン一覧ダイアログ（`PlanListDialog`）

ヘッダーの `[プラン一覧]` から開くモーダル。

```text
┌─ プラン一覧 ────────────────────────────────────────────────────────┐
│ [+ 新規作成]                              [JSONから読み込む]         │
│                                                                     │
│  名前            種別  ゲーム         更新日時           操作         │
│  エース候補A      投手  パワプロ2024   2026-08-30 14:22  [開く][複製][削除] │
│  4番打者B        野手  パワプロ2024   2026-08-29 09:10  [開く][複製][削除] │
└─────────────────────────────────────────────────────────────────────┘
```

| 操作 | 規定 |
|---|---|
| 新規作成 | 名前 `新規プラン`、種別=投手、センス○=あり、ゲーム=現在選択中 で作成し、タブ1を開く。 |
| 複製 | 名前に ` のコピー` を付与し、新しい `id` / `createdAt` / `updatedAt` を採番する。 |
| 削除 | 「プラン『〇〇』を削除します。元に戻せません。よろしいですか？」の確認ダイアログを必須とする。 |
| 並び順 | `updatedAt` 降順。 |

## 9. 入力バリデーションの表示規則

| 種類 | 表示 |
|---|---|
| 入力形式エラー（範囲外・非整数） | 該当入力欄を赤枠にし、直下に赤字で理由を表示。**再計算は行うが、その項目は `INVALID_TARGET` として issue に載せる**。 |
| データ不足 | 該当行に ⚠ アイコンと理由を表示。計算結果タブの不足一覧にも載せる。 |
| ロードエラー | タブ1に赤枠パネル。他タブは操作不可。 |

入力欄は**空文字を許容しない**。空にした場合は直前の有効値へ戻す（`onBlur` 時）。

## 10. アクセシビリティ・操作性

| 項目 | 規定 |
|---|---|
| キーボード操作 | すべての入力欄・ボタンが Tab で到達でき、Enter / Space で操作できること。 |
| フォーカス表示 | ブラウザ既定のフォーカスリングを消さないこと。 |
| ラベル | すべての入力欄に `<label>` を関連付けること。 |
| 色のみに依存しない | ステータス・出どころは色に加えて必ずテキストを併記すること。 |
| `aria-live` | 再計算完了時に合計値の変化をスクリーンリーダーへ通知する `[SHOULD]`。 |
| 自動テスト用属性 | E2Eで使用する要素に `data-testid` を付与する（命名は `13_e2e_test_spec.md` §3 に従う）。 |

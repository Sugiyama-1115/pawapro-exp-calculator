# 01. 要件定義

---

## 1. システムの目的

サクセスで育成する選手について、以下を入力すると完成までに必要な経験点を算出する。

**入力**

- ゲームバージョン / 選手種別（投手・野手）/ sense_mode
- 初期基礎能力・目標基礎能力
- 初期特殊能力・目標特殊能力（青特 / 金特）
- 各特殊能力のコツLv
- 目標変化球構成

**出力**

- 筋力 / 敏捷 / 技術 / 変化球 / 精神 の各合計と総合計
- 基礎能力・青特・金特・変化球ごとの消費内訳
- 各項目の値の出どころ（実測 / 推定 / マスタ / 手動）
- 未入力・未登録データの一覧

---

## 2. 利用者・利用シーン

| 項目 | 内容 |
|---|---|
| 想定利用者 | パワプロのサクセスモードで選手を育成する個人プレイヤー |
| 同時利用者数 | 1（マルチユーザ・認証は対象外） |
| 利用環境 | PC の Chromium系ブラウザ最新版 |
| 利用タイミング | サクセス開始前の計画立案時、および育成中の進捗確認時 |
| データ入力者 | 利用者本人（ゲーム画面の表示値を CSV に手入力する） |

## 3. 機能要件一覧

各要件に ID を付与する。試験項目はこの ID を参照する。

### 3.1 ゲームデータ管理（FR-D）

| ID | 要件 |
|---|---|
| FR-D-01 | 起動時に `public/data/games.json` を読み込み、選択可能なゲームバージョン一覧を表示する。 |
| FR-D-02 | ゲームバージョンを選択すると、そのディレクトリ配下のCSVのみをロードする。他バージョンのデータは一切参照しない。 |
| FR-D-03 | ロードしたCSVは `03_data_spec.md` の検証ルールで全件検証する。1件でも違反があればロードを中止し、エラー内容を画面に表示する。 |
| FR-D-04 | 検証を通過したCSVはメモリ上のインデックス（Map）へ展開し、以後のCSVファイル再読込を行わない。 |
| FR-D-05 | ゲームバージョンを切り替えた場合、前バージョンのインデックスを破棄し、新バージョンのCSVを再ロードする。 |
| FR-D-06 | ユーザーが任意のCSVファイルを読み込んで標準データを上書きできる（種別ごと：基礎能力 / 青特 / 金特 / 金特前提 / コツ倍率 / 変化球キャッシュ / config）。 |
| FR-D-07 | インポートしたデータは同一キーの標準データより優先する。優先関係は画面上で確認できる。 |
| FR-D-08 | インポートしたデータは IndexedDB に保存し、再起動後も維持される。種別単位で破棄できる。 |

### 3.2 選手計画（FR-P）

| ID | 要件 |
|---|---|
| FR-P-01 | 選手計画を新規作成できる。作成時に ゲームバージョン / 選手名 / 選手種別 / sense_mode を指定する。 |
| FR-P-02 | 選手計画を複数保存でき、一覧から開ける。 |
| FR-P-03 | 選手計画を複製できる。複製時は名前に ` のコピー` を付与する。 |
| FR-P-04 | 選手計画を削除できる。削除前に確認ダイアログを表示する。 |
| FR-P-05 | 入力内容の変更は自動保存する（デバウンス 500ms）。 |
| FR-P-06 | 選手計画を JSON でエクスポート／インポートできる。 |

### 3.3 基礎能力（FR-B）

| ID | 要件 |
|---|---|
| FR-B-01 | 選手種別に応じた基礎能力項目を表形式で表示する。 |
| FR-B-02 | 各能力について初期値と目標値を入力できる。 |
| FR-B-03 | 初期値から目標値までの各1段階分のCSV行を積み上げて必要経験点を算出する。 |
| FR-B-04 | 目標値 < 初期値 の場合は `INVALID_TARGET` として当該行をエラー表示する。 |
| FR-B-05 | 目標値 = 初期値 の場合、その能力の必要経験点は 0 とする（データ不足ではない）。 |
| FR-B-06 | 途中の遷移行がCSVに存在しない場合、0 補完せず `BASE_DATA_MISSING` とする。 |
| FR-B-07 | 投手であっても野手基礎能力を入力できるデータ構造を持つ。MVPのUIでは折りたたみ領域として提供し、開いた場合は投手基礎能力表の直下に野手基礎能力表を表示する（**投手→野手の順**）。野手プランでは野手基礎能力のみを表示する。 |

### 3.4 青特殊能力（FR-BL）

| ID | 要件 |
|---|---|
| FR-BL-01 | 青特を検索（部分一致・表示名 / ID）して一覧から選択できる。 |
| FR-BL-02 | `binary` 型は 現在状態（NONE/ON）と目標状態（NONE/ON）を指定できる。 |
| FR-BL-03 | `rank` 型は 現在ランクと目標ランクを G〜A から指定できる。 |
| FR-BL-04 | `rank` 型は 現在→目標 の間の各遷移行のみを積み上げる。 |
| FR-BL-05 | 各青特にコツLv（0〜5）を指定できる。 |
| FR-BL-06 | 必要経験点 = `丸め(CSV基礎値 × コツ倍率 × センス倍率)` とし、5カテゴリを独立して丸める。 |
| FR-BL-07 | 現在状態 = 目標状態 の場合、必要経験点は 0 とする。 |
| FR-BL-08 | 目標状態が現在状態より下位の場合は `INVALID_TARGET` とする。 |
| FR-BL-09 | 投手プランでも `player_type=fielder` 限定の青特・金特を検索・選択・計算できる（野手専用能力）。計算は各能力自身のマスタ上の `player_type` に基づいて行う。検索結果および選択中一覧は「`player_type` が `pitcher`/`common` の能力」→「`player_type=fielder` の能力（野手専用）」の順に表示する。野手プランは従来どおり `fielder`/`common` の能力のみを対象とする。 |

### 3.5 金特殊能力（FR-G）

| ID | 要件 |
|---|---|
| FR-G-01 | 金特を検索して選択できる。 |
| FR-G-02 | 金特を選択すると、`gold_prerequisites.csv` に定義された下位青特を自動的に必要能力へ追加し、画面に表示する。 |
| FR-G-03 | 下位青特のコツLvと金特のコツLvは個別に指定できる。 |
| FR-G-04 | 下位青特を既に所持している場合、その青特の必要経験点は 0 とする。 |
| FR-G-05 | ユーザーが下位青特を明示指定していても、同一青特を二重計算しない。 |
| FR-G-06 | 対象コツLvの実測値が存在する場合、推定処理を行わず実測値を使用する。 |
| FR-G-07 | 対象コツLvの実測値がなく、他Lvの実測値が1件以上ある場合、仮想基礎値Bを逆算して推定する。 |
| FR-G-08 | 当該金特の実測値が1件も存在しない場合、`GOLD_DATA_MISSING` とする。他の金特から推定してはならない。 |
| FR-G-09 | 各金特の値について 実測 / 高信頼推定 / 推定 / データ不足 の4状態を表示する。 |

### 3.6 変化球（FR-BR）

| ID | 要件 |
|---|---|
| FR-BR-01 | 目標変化球構成（球種と変化量）を入力できる。 |
| FR-BR-02 | 一括実測方式（合計経験点のみ入力）を提供する。 |
| FR-BR-03 | ステップ実測方式（取得手順ごとに入力）を提供する。 |
| FR-BR-04 | 使用データの優先順位は 「① プランの一括実測値 → ② プランのステップ実測値 → ③ 共通キャッシュ完全一致 → ④ 手動入力要求」 とする。 |
| FR-BR-05 | 変化球の必要経験点を**推定してはならない**。データがなければ `BREAKING_DATA_MISSING` とする。 |
| FR-BR-06 | 入力したステップ実測値を共通キャッシュへ登録できる。 |
| FR-BR-07 | 共通キャッシュはキー完全一致でのみ再利用する。部分一致・近似は禁止。 |
| FR-BR-08 | 野手プランでは変化球タブを非表示にする。 |

### 3.7 計算結果（FR-R）

| ID | 要件 |
|---|---|
| FR-R-01 | 5カテゴリの合計と総合計を表示する。 |
| FR-R-02 | 基礎能力 / 青特 / 金特 / 変化球 の内訳を項目単位で表示する。 |
| FR-R-03 | 各項目に出どころバッジ（マスタ / 実測 / 高信頼推定 / 推定 / 手動）を表示する。 |
| FR-R-04 | 結果全体のステータスを 確定 / 推定含む / 未完成 の3状態で表示する。 |
| FR-R-05 | 不足データの一覧（何がなぜ足りないか）を表示する。 |
| FR-R-06 | 入力変更時に自動で再計算する（デバウンス 200ms）。 |
| FR-R-07 | 計算結果を CSV / JSON でエクスポートできる。 |
| FR-R-08 | 結果サマリー（合計値とステータス）は全タブで常時表示する。 |

## 4. 非対象（スコープ外）

以下は本プロジェクトの対象外とする。実装してはならない。

- 練習・試合・イベントで獲得できる経験点の予測
- ダイジョーブ博士の成功確率、イベント発生確率
- 継承選手から取得できるコツLvの予測
- サクセス内での最適行動選択・シミュレーション
- 変化球必要経験点の数式推定
- 認証、マルチユーザ、サーバー同期
- スマートフォン専用レイアウト
- 多言語対応
- オフラインインストール（PWA）

## 5. 前提・制約

| 項目 | 内容 |
|---|---|
| データ精度 | CSVの値は利用者が手入力する。アプリはCSVの値が正しいことを検証できない（形式検証のみ行う）。 |
| 初回状態 | クローン直後は `sample2024`（ダミー値）のみ利用可能。実データは利用者がCSVを配置またはインポートする。 |
| 実測データの秘匿 | `public/data/pawapro*/` は `.gitignore` 対象。リポジトリへコミットしてはならない。 |
| 数値範囲 | 経験点は 0 以上の整数。上限は 99,999 とする（超過はCSV検証エラー）。 |
| 計算量 | CSV総行数は最大 50,000 行程度を想定。全件メモリ展開して問題ない規模とする。 |

## 6. MVP 完了条件

`14_acceptance_test.md` の受け入れ試験項目がすべて合格すること。完了条件の原文は以下の19項目とする。

1. 初期基礎能力を入力できる
2. 目標基礎能力を入力できる
3. CSVから基礎能力経験点を計算できる
4. 青特を選択できる
5. 青特コツLvを指定できる
6. ランク青特を計算できる
7. 金特を選択できる
8. 下位青特を自動追加できる
9. 金特コツLvを指定できる
10. 金特実測値を利用できる
11. 未実測金特を推定できる
12. 推定値と実測値を区別できる
13. 変化球経験点を手動入力できる
14. 変化球ステップデータを再利用できる
15. 5種類の経験点合計を表示できる
16. 各能力別の内訳を確認できる
17. データ不足を検出できる
18. ゲームデータをCSVで差し替えられる
19. 新作をコード変更なしで追加できる
